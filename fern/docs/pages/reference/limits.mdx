Defaults apply to every account unless raised. The ones that matter operationally are at the top. If you're planning a launch, share your expected peak concurrent calls with support ahead of time — raising a limit is routine; discovering it mid-campaign is not.

## Calls

| Limit | Default | At the ceiling |
|---|---|---|
| Concurrent calls per account (inbound + outbound + browser) | **10** | outbound calls queue (HTTP `202`); inbound calls beyond capacity are refused |
| Queue depth | **100** | new outbound calls refused with `queue_full` |
| Call placements per minute | **60** | refused with `rate_limit_exceeded` |
| Minimum balance to start a call | **$1.00** | refused with `insufficient_balance`; inbound answered busy |
| Maximum single-call telephony charge | $500 | the charge is rejected for review rather than billed — an anti-fraud backstop |
| Per-flow maximum call length | off by default; 30 s – 4 h when set | agent says goodbye and hangs up |

The account's current values are visible in the dashboard's account settings.

## Queue behaviour

When every concurrent slot is busy, outbound calls wait in a priority queue and are placed as slots free up.

| Factor | Effect on order |
|---|---|
| **Direct** calls (API, dashboard, callbacks) | always ahead of scheduled and campaign work |
| **Scheduled** calls | ahead of campaign calls — the user chose the time |
| **Campaign** calls | lowest priority; they're designed to wait |
| **Warm** leads (e.g. a fresh Meta lead) | a modest boost within their class |
| **Waiting time** | every minute in the queue improves priority, up to a cap at 15 minutes — nothing starves |

Queue entries expire — a direct call after **60 s**, a scheduled call after **10 min**, a campaign call after **24 h** (or the campaign's end time) — so a call is never placed long after it made sense.

| Limit | Value |
|---|---|
| API keys per account | 25 |
| Contacts per add-to-campaign request | 1,000 (use the filter-based bulk add for more) |
| DNC numbers per bulk import | 10,000 |
| DNC numbers per check | 100 |
| Contact secondary phones | 10 |
| Contact tags | 50 |
| Contact notes | 5,000 characters |
| Flow function timeout | 100 ms – 30 s (35 s hard cap at dispatch) |
| Flow function request / response body | 1 MB each |
| Prompt template / idle end message / duration-cap message | 1,000 characters |
| Real-time WebSocket connections per account | 20 |
| Subscriptions per WebSocket connection | 50 |
| Assistant prompts | 10 per minute |
| Data exports | one at a time; 24 h between completed exports |

## Campaigns and schedules

| Limit | Value |
|---|---|
| Campaign concurrency | 1 – 50, default 5 (also bounded by the account's concurrent-call limit) |
| Campaign attempts per contact | 3 |
| Schedule retries per run | 0 – 10, default 2; delay 1 – 1,440 min, default 30 |
| Schedule monthly day-of-month | 1 – 28 |

## Numbers and billing
